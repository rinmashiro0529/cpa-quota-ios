# 实时活动与监控启用

安装包含 ActivityKit/WidgetKit 扩展的新版 App 后，系统实时活动仍需用户主动启动，后台更新还需独立监控服务和可用 APNs 身份。仅连接 CPA、添加桌面 Widget 或允许普通通知，不会自动建立监控活动。

## 先准备独立服务

按 [监控部署](MONITOR_DEPLOYMENT.md) 配置可信 HTTPS、CPA 来源、明确账号白名单、独立桥接 token 和加密状态。服务中的 `sources[].id` 是手机要填写的来源标识；不是服务器 URL、账号邮箱或自动生成的连接名称。示例配置的来源为 `personal` 时，手机也填 `personal`。

Development 包必须与服务端 Sandbox APNs 环境匹配；分发包应核对其实际签名环境。`apns.bundle_id` 使用主 App 的 `icu.nahida.cpaquota`，不是扩展的 `.activity` 标识，服务自行添加 `.push-type.liveactivity`。私钥只在服务端，CPA 管理密钥、桥接 token 和活动 push token 不能相互替代。

`dry_run=true` 仅禁止 APNs，有有效活动时仍可能采集 CPA；它不是完全离线开关。服务合并到 main 或构建成功不会自动部署、获取授权或生成真实设备 token。

## 手机设置与开始监控

1. 在系统设置中找到 App 的实时活动权限并允许；返回 App 后会重新读取系统授权。
2. 在「连接管理」配置自己的 CPA，以便读取账号候选；独立服务最终仍按自己的白名单校验，候选存在不等于已授权监控。
3. 在「监控与活动」打开「连接监控服务」，填写监控 HTTPS 地址和独立桥接 token，点击连接。表单的“连接配置就绪”不是一次已经通过的网络或授权检查。
4. 返回监控主页面，手动填写服务配置中的来源标识，选择一至五个获授权账号，并选一、四或八小时。连接不会自动填来源或选择账号；先以最小范围验证。
5. 点击「开始监控」，等待系统创建活动并自动取得 push token。无需手工复制 token，也不要使用虚构值测试推送。首次采集前可以点一次「请求更新读数」，再返回桌面或锁屏观察真实显示。

## 开始监控不可点击

| 条件 | 检查方式 |
| --- | --- |
| 监控连接仍未配置 | 不仅填写字段，还需点击连接并返回主页面 |
| 来源为空或只有空白 | 填写与服务端一致的 Source ID |
| 未选账号 | 监控账号必须显示一至五个，不是零 |
| 系统实时活动未允许 | 根据页面提示打开系统设置后返回 |
| 当前平台不支持 | 系统活动入口要求受支持的 Apple 移动平台；Linux 模型测试不能证明它可用 |
| 仍有连接、会话、token 轮换或缓存请求进行中 | 页面可能显示正在连接或正在处理；记录该状态，不通过删除恢复记录或重装绕过 |

按钮颜色不是可点击状态的可靠证明。以上是源码中的启用条件，不是对任何一台手机故障根因的断言；条件均满足仍不能点击时，需要实际界面或运行证据。截图前遮挡令牌、邮箱及其他私人信息，不能用健康检查通过替代手机状态验证。

## 验收和停止

健康 200、受理 202、会话 active、APNs sent/ended 与设备实际展示是不同状态。首次没有缓存时授权 quota GET 返回404可以是正常结果；同来源约600秒采集是服务目标，不保证设备每十分钟更新。系统控制紧凑、最小、展开和锁屏呈现；当前不承诺后台自动轮播账号。

“仅停止本机实时活动显示”不会取消远端采集。“停止监控”需要服务端确认持久取消；超时或未知404都不能当作已经停止。不要删除加密状态、取消墓碑或清空 Keychain 来掩盖未确认结果。

当前仓库没有普通额度告警横幅/声音通知链路，也不通过服务端远程创建活动。真实额度、后台更新、设备离线、强退、锁屏隐私和APNs送达须用授权的真实活动逐项验收。
